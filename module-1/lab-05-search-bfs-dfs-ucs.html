Uninformed Search — BFS, DFS & UCS

When an intelligent agent knows the start state, possible actions and goal test but has no additional information about how close each state is to the goal, it can use uninformed (blind) search. This lab makes the three core strategies visual: Depth-First Search, Breadth-First Search and Uniform-Cost Search.

🔎 Blind Search
No heuristic estimate of goal closeness.
📚 BFS
Explore shallowest nodes first using FIFO.
🧗 DFS
Explore deepest available node first using LIFO.
💰 UCS
Expand the lowest cumulative path cost first.

3 · Search Problem Vocabulary

The building blocks of a search problem

Problem Graph

Represents states and connections from start S toward goal G.

Strategy

The rule deciding which node/path is explored next.

Fringe / Frontier

Data structure containing states that can be reached and are waiting for exploration.

Search Tree

The path/tree representation generated while searching.

Solution Plan

Sequence of states/actions that transforms S into G.

Path / Step Cost

Integer/action costs used to measure the cost of moving between nodes.

These six terms are explicitly listed in the VTU Module 1 uninformed-search material. fileciteturn22file5

4 · How We Evaluate Search

Four important questions

1. Complete?

Will the algorithm find a solution if one exists, subject to the stated conditions?

2. Optimal?

Will it return a solution with the lowest path cost?

3. Time?

How many nodes may need to be generated/expanded?

4. Space?

How much memory may be required for the frontier/reached information?

Reema Thareja identifies optimality as obtaining the lowest path cost and defines time/space complexity in terms of execution effort and storage requirements. fileciteturn22file9

5 · Breadth-First Search

BFS — Shallowest node first

Idea: BFS explores the tree level by level. It starts at the root, expands all nodes at the current depth, then moves to the next depth. The VTU example finds S → D → G because G is the shallowest solution. fileciteturn22file7

S
Depth 0
→
A · B · C
Depth 1
→
D · E · F · G
Depth 2
Data structure: FIFO Queue — first node inserted is the first node removed. The queue allows BFS to finish one level before moving deeper. Reema Thareja describes BFS as a FIFO-queue algorithm. fileciteturn21file15

Typical BFS sequence

  1. Insert the start node into the queue.
  2. Remove the front node and test it.
  3. Add its unvisited children to the rear of the queue.
  4. Repeat until the goal is found or the queue becomes empty.
6 · BFS Properties

Why BFS is useful — and expensive

PropertyBFS
CompletenessComplete under the standard finite-branching conditions described in the sources.
OptimalityOptimal when all step costs are equal; Reema Thareja states this as step cost = 1 / equal costs. fileciteturn21file15
TimeO(bd) in the standard tree-search formulation, where b is branching factor and d is shallowest solution depth. fileciteturn22file17
SpaceO(bd) in the standard tree-search formulation because many frontier nodes remain in memory. fileciteturn22file17
AdvantageFinds the shallowest solution and does not get stuck following one infinitely deep branch.
DisadvantageCan require very large memory because the frontier grows rapidly.

Real-life applications named in Reema Thareja include web crawlers, GPS navigation for neighbouring locations, shortest paths in unweighted graphs, network broadcasting and peer-to-peer networking. fileciteturn21file3

7 · Depth-First Search

DFS — Go deep, then backtrack

DFS starts at the root and follows a branch toward a leaf/deep node. If the goal is not found, it backtracks to the most recent point with an unexplored branch and continues. Reema Thareja's example traces A → B → D → H, then backtracks to explore other branches. fileciteturn22file9

A
↓
B
↓
D
↓
H
Data structure: LIFO Stack — the most recently added node is explored first. This is why DFS naturally moves down one branch before considering siblings.

DFS sequence

  1. Push the start node.
  2. Pop the deepest/latest available node.
  3. If it is not the goal, add its successors.
  4. Continue down a branch; when necessary, backtrack.
8 · DFS Properties

Memory efficient, but can go the wrong way for a long time

PropertyDFS
MemoryStores mainly the current path/fringe, so it can use less memory than BFS.
TimeO(bm) in the standard tree formulation, where m is maximum depth. fileciteturn22file9
SpaceO(bm) in the formulation given by Reema Thareja. fileciteturn22file9
CompletenessNot guaranteed in general; an infinite path can prevent the algorithm from reaching a solution elsewhere.
OptimalityNot guaranteed to return the lowest-cost or shallowest solution.
RisksRecurring states, infinite loops and duplicate nodes can create inefficiency. fileciteturn22file1
Depth problem: a cut-off can prevent an infinite descent, but a limit that is too small can miss the goal; a limit that is too large can increase execution time. fileciteturn22file1
9 · Uniform-Cost Search

UCS — Cheapest path first

When actions have different costs, simply choosing the shallowest path is not enough. UCS expands the node with the lowest cumulative path cost from the start. The VTU example finds S → A → B → G with total cost 5. fileciteturn22file4

S
cost +2
A
cost +1
B
cost +2
G
Priority queue: UCS gives highest priority to the node with the smallest cumulative path cost. It is not depth-first and not breadth-first; it expands in increasing path-cost order. fileciteturn22file15

Cost calculation

g(n) = cumulative cost from S to n
S = 0 → A = 2 → B = 3 → G = 5.

10 · UCS Properties

Why cost changes the answer

PropertyUCS
Selection ruleLowest cumulative path cost g(n).
Data structurePriority queue.
CompletenessComplete under conditions such as finite branching and action costs bounded below by ε > 0; Reema Thareja also notes no zero-weight loop for its stated condition. fileciteturn22file15
OptimalityOptimal when action costs are non-negative/under the source's stated conditions; it selects paths in increasing cost order. fileciteturn22file15
AdvantageFinds an optimal solution based on actual path cost when its assumptions hold.
DisadvantageMay explore many nodes and require substantial memory; it has no information about where the goal is. fileciteturn22file15

13 · Worked Example

Why BFS and UCS can return different paths

Imagine two routes from S to G:

Route 1 — shallow

S → A → G

2 edges, but expensive: 9 + 9 = 18.

Route 2 — deeper

S → B → C → G

3 edges, but cheap: 2 + 2 + 2 = 6.

BFS prefers the shallow solution because it ignores path cost. UCS prefers the cheaper route because it compares cumulative cost. This illustrates why BFS is optimal for equal step costs but not for arbitrary unequal costs.

14 · Algorithm Selection Guide

Which one should you think of first?

📚 Choose BFS when…

The solution is likely shallow and actions have equal cost; you want the minimum number of steps.

🧗 Choose DFS when…

Memory is constrained and deep solutions may be useful, but you can tolerate lack of completeness/optimality.

💰 Choose UCS when…

Step costs differ and the objective is the lowest total path cost.

If you have useful information about how close a node is to the goal, you are moving toward informed/heuristic search, which is the subject of the next search lessons.

16 · Common Misconceptions
“BFS always finds the cheapest path.”

Only when the step costs satisfy the equal-cost condition used in the course treatment. With unequal costs, UCS is the appropriate uninformed cost-based strategy.

“DFS always finds the shortest path because it reaches a goal quickly.”

No. DFS may find a deep, expensive or otherwise non-optimal solution before a better one.

“UCS is a heuristic search.”

No. UCS uses actual cumulative path cost, not a heuristic estimate of remaining cost. It is treated as an uninformed strategy.

“Blind search means random search.”

No. BFS, DFS and UCS are systematic strategies. “Blind” refers to the absence of extra information about goal location.

“The first node generated by UCS must be the optimal solution.”

The algorithm's goal-testing/expansion conditions matter. The standard UCS formulation returns a goal when the least-cost node is selected for expansion; this supports cost optimality under the stated assumptions.

18 · Takeaways
  • Uninformed search has no extra information about how close a state is to the goal.
  • BFS = FIFO + shallowest first.
  • DFS = LIFO + deepest first + backtracking.
  • UCS = priority queue + lowest cumulative path cost.
  • BFS is optimal for equal step costs; UCS is designed for varying costs under its assumptions.
  • DFS uses less memory than BFS in the standard treatment but can get trapped in an infinite/deep branch.
  • Always state the selection rule and data structure when explaining a search algorithm.
